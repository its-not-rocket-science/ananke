Performance Dashboard

Tracks how many simulation ticks Ananke can advance per second across commits, and compares throughput against alternative approaches.

What does "ticks/sec" mean?

One tick advances the entire simulation world by one time-step — resolving all physics, combat, conditions, and entity state. The benchmark runs a "large battle" scenario (many entities in active combat) for 10 seconds of wall-clock time and counts how many ticks completed.

Higher is better. At 100 ticks/sec you can simulate ~100 game-seconds per real second at 1 Hz, or run 6000× real-time at 60 Hz tick rate. The WASM core column shows the raw kernel isolated from JS orchestration overhead — it is not a like-for-like comparison with the TypeScript host.

Benchmarks run on the CI runner (GitHub Actions, Ubuntu, Node 20). Numbers vary ±5% between runs. Use the trend line, not individual data points.

Methodology

Scenario: 12 entities, mixed weapon loadouts, 60-second simulation at 1 Hz. Runs 5× per commit, median reported. Outliers (>2σ) discarded.

Why WASM so fast?

The WASM core skips the JS event loop and host orchestration. It benchmarks raw kernel throughput — useful for capacity planning but not representative of a real host integration.
